# Contributing

## Development workflow

1. Create a feature branch from `main`.
2. Keep pull requests focused on one problem.
3. Run `.NET` build and Python syntax checks before opening a pull request.
4. Update documentation when behavior or build steps change.
5. Do not commit generated binaries, model weights, credentials or user media.

## Commit messages

Use conventional, readable messages, for example:

```text
feat(ai): add ROI-only inpainting
fix(installer): keep delogo boxes inside frame bounds
docs(release): document GitHub release assets
```

## Pull requests

Include:

- problem statement
- implementation summary
- verification steps
- screenshots for UI changes
- note about release packaging impact
